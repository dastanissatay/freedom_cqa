# CQA — Conversation Quality Analytics

Прототип автоматической оценки работы операторов поддержки по диалогам (чаты и звонки, RU / KZ / EN) с помощью LLM.
Хакатон Freedom Broker.

- **Контур 1 · Оценка:** настраиваемый чек-лист (секции, веса, Да/Нет, шкалы, N/A с условием, флаг грубой ошибки) с версиями → оценка диалога одним вызовом LLM → детерминированный расчёт баллов в коде → обоснование по каждому критерию со ссылками на реплики.
- **Контур 2 · Работа с результатом:** карточка диалога (транскрипт + аудиоплеер для звонков, переход к реплике/моменту записи), апелляции (роль «Оператор/Супервайзер»), решения проверяющего (роль «Проверяющий») с пересчётом итога без повторного вызова LLM.
- **Пакетная оценка** контрольного набора с прогрессом и экспортом CSV/JSON.

**Стек:** Python 3.11+ · FastAPI · SQLite · чистый HTML/CSS/JS (ES-модули, без сборки) · LLM через адаптер (Claude API / любой OpenAI-совместимый сервер / mock).

## Быстрый старт

```bash
git clone <repo> && cd freedomDataChallenge
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # затем заполнить .env (см. ниже)
uvicorn app.main:app --app-dir backend --port 8000
```

Открыть **http://localhost:8000** (редирект на `/web/index.html`).

Минимальные настройки в `.env`:

| Переменная | Что указать |
|---|---|
| `DATASET_API_URL` | URL API организаторов **без** параметров; `group_id` подставляется из интерфейса (`?group_id=DEV`) |
| `LLM_PROVIDER` | `anthropic` (по умолчанию), `openai_compat` или `mock` |
| `ANTHROPIC_API_KEY` | ключ Claude API (для `anthropic`) |
| `LLM_MODEL` | по умолчанию `claude-opus-5-5`; дешевле — `claude-sonnet-5-5` |

API-ключи хранятся только в `.env` (он в `.gitignore`); шаблон — `.env.example`.

**Без ключа и без доступа к API данных:** поставьте `LLM_PROVIDER=mock`, введите в шапке `group_id` = `SAMPLE`, нажмите «⇪ Импорт JSON» и выберите `data/sample_dataset.json`. Mock-модель выдаёт детерминированные вердикты по простым правилам — так можно проверить весь интерфейс.

### Своя модель на GPU (vLLM / Ollama / OpenRouter)

```bash
vllm serve Qwen/Qwen2.5-72B-Instruct --port 8001     # пример
```
```ini
LLM_PROVIDER=openai_compat
OPENAI_BASE_URL=http://<gpu-host>:8001/v1
LLM_MODEL=Qwen/Qwen2.5-72B-Instruct
PRICE_INPUT_PER_M=0
PRICE_OUTPUT_PER_M=0
```
Адаптер передаёт `temperature=0` и `response_format=json_schema` (guided decoding в vLLM). Если сервер схему не поддерживает, адаптер переходит на `json_object`, а затем на обычный текст. Ответ в любом случае проверяется в коде.

## Как пользоваться (сценарий защиты, 5 минут)

1. **Интерфейс и диалог.** «Диалоги» → список с каналом, языком, итогом и флагами → клик по диалогу открывает карточку: слева транскрипт (у звонков ещё аудиоплеер), справа результат.
2. **Оценка.** В шапке выбран чек-лист → «▶ Оценить». В результате видны итог, итоги по секциям и по каждому критерию: ответ, баллы / вес, объяснение и ссылки:
   - `↗ [5] Оператор 00:40` — прокрутка к реплике с подсветкой (у звонков плеер переходит на `timestamp − timestamp первой реплики`);
   - `⌕ Проверенный участок [3]–[8]` — где ожидалось пропущенное действие;
   - **Причина N/A** — какое условие неприменимости выполнено (вес перераспределён);
   - грубая ошибка выводится отдельным красным блоком и на баллы не влияет.
3. **Апелляция.** Роль «Оператор / Супервайзер» → «⚑ Обжаловать» у критерия → комментарий → «Сохранить апелляцию».
4. **Решение проверяющего.** Роль «Проверяющий» → «Апелляции»: спорная оценка, обоснование LLM, комментарий и фрагмент диалога → «Подтвердить» или «Изменить на …» + причина → итог пересчитан (исходный → финальный). В карточке видны исходная оценка, решение и финальный результат.
5. **Изменение критерия.** «Чек-листы» → развернуть критерий → изменить формулировку, вес, тип, N/A и шкалу (или «+ критерий» и удалить старый) → «Сохранить как новый чек-лист» (или «как новую версию»). Сохранённая версия сразу становится активной. Дальше — «Оценить» в карточке или «Пакетная оценка». Код менять не нужно: промпт и JSON-схема строятся из конфигурации.

### Проверка качества LLM: эталонная разметка
В наборе от организаторов нет эталонных оценок, поэтому качество проверяется на собственной ручной разметке:
1. В карточке диалога нажмите «✎ Эталон» и отметьте правильный ответ по каждому критерию. Пока критерий не размечен, ответ LLM по нему скрыт, чтобы не подсказывать. При желании добавьте комментарий. Сохранённый эталон привязан к версии чек-листа.
2. Разметьте 10–15 разных диалогов (RU/KZ/EN, звонки, с нарушениями и без) и оцените их LLM. Неоценённые можно отправить на оценку прямо со страницы «Качество».
3. Страница **«Качество»** показывает:
   - процент совпадения ответов LLM с эталоном по каждому критерию и в целом;
   - **каппу Коэна** — меру согласия с поправкой на случайные совпадения;
   - расхождения по N/A и ошибку шкальных критериев (в % от максимума шкалы);
   - среднее отклонение итогового балла (MAE) и долю диалогов, где итог отличается не больше чем на 5 или 10 баллов;
   - найденные, ложные и пропущенные грубые ошибки;
   - список расхождений с обоснованием LLM и ссылкой на диалог.
4. В карточке оценённого диалога у каждого критерия видно, совпадает ли ответ LLM с эталоном.

Сравнивается исходный ответ LLM (до апелляций) из последней оценки этой версией чек-листа. Эталон можно загрузить из JSON («⇪ Импорт эталона»): `{"items":[{"conversation_id":"p1-ru-001","answers":{"01":"yes","02":"na","04":15}, "notes":{"04":"..."}}]}`. Если организаторы дадут эталонные ответы, их можно сразу загрузить и посчитать согласие. API: `PUT/GET/DELETE /api/references/{group_id}/{conversation_id}`, `POST /api/references/import`, `GET /api/quality?group_id=&checklist_version_id=`.

### Контрольный набор (через 23 часа после старта)
Ввести новый `group_id` в шапке → «Пакетная оценка» → «1. Загрузить набор из API» → «2. Оценить все диалоги» (прогресс, ошибки, стоимость) → «3. Экспорт» CSV или JSON (с обоснованиями).

## Архитектура

```
web/ (HTML+JS компоненты) ──fetch──▶ FastAPI (backend/app)
                                      ├─ dataset.py    прокси к API организаторов (нет CORS), кэш в SQLite, offset_sec, аудио-прокси с Range
                                      ├─ checklists.py CRUD чек-листов, каждая правка = новая неизменяемая версия
                                      ├─ prompt.py     промпт + JSON Schema ← из конфигурации чек-листа
                                      ├─ llm/          адаптеры: anthropic | openai_compat | mock (LLM_PROVIDER)
                                      ├─ validation.py проверка ответа LLM → повтор с перечнем ошибок
                                      ├─ scoring.py    детерминированный расчёт (чистые функции, юнит-тесты)
                                      ├─ evaluator.py  1 вызов LLM на диалог → валидация → расчёт → сохранение
                                      ├─ appeals.py    апелляции/решения, пересчёт финального итога кодом
                                      └─ batch.py      пакетная оценка (asyncio + семафор), прогресс, экспорт
```

### Контракт LLM
Модель возвращает **только вердикты**, без баллов. Структура задаётся через structured outputs (JSON Schema строится из чек-листа: `answer` — enum только допустимых значений, `na` только там, где N/A разрешён):
```json
{"verdicts": {"03": {"evidence": [5, 7], "checked_range": [3, 8], "explanation": "Нет. Оператор раскрыл ...", "answer": "no"}}}
```
Код приводит ответ к списку `{criterion_id, answer, explanation, evidence, checked_range}` и проверяет его: все критерии на месте ровно по одному разу; значения допустимы; N/A только где разрешён; индексы реплик существуют; у ответа «Нет» есть доказательство или проверенный участок; объяснение не пустое. При ошибке модель вызывается повторно (до `LLM_MAX_RETRIES`) с перечнем ошибок в промпте.

Реплики в промпте пронумерованы `[i] speaker timestamp: text`, по этим индексам UI строит якоря. Оценивается только `operator`, а `bot` и `system` служат контекстом. Объяснения всегда на русском. Пояснения к чек-листу из ТЗ хранятся в поле `instructions` конфигурации и тоже попадают в промпт.

**temperature.** На актуальных моделях Claude параметр `temperature` удалён из API: запрос с ним возвращает 400. Поэтому адаптер `anthropic` его не передаёт. Воспроизводимость обеспечивают строгая схема ответа, умеренный `effort`, валидация и детерминированный расчёт. В адаптере `openai_compat` `temperature=0`.

### Расчёт (только в коде, `scoring.py`)
1. N/A допускается, только если он разрешён у критерия (иначе это ошибка).
2. «Да» даёт полный вес, «Нет» — 0; шкала: `ступень / максимум × вес`.
3. Итог = `сумма набранных / сумма весов применимых × 100`, округление до 2 знаков (half-up). Если применимых критериев с весом нет, итог = `null`.
4. Критерии типа `flag` (грубые ошибки) идут отдельным флагом и не влияют на баллы. Итоги по секциям считаются так же.

### Хранилище (SQLite, `data/cqa.db`)
- `checklists`, `checklist_versions(config_json)` — версии неизменяемы.
- `conversations` — кэш набора по `group_id`; исходные `timestamp` сохраняются, а `offset_sec` вычисляется.
- `evaluations` — ссылка на `checklist_version_id`, вердикты LLM, исходный результат, usage, стоимость.
- `appeals` — критерий, комментарий, исходное значение, статус, решение (`confirm` / `change`), новое значение, причина, время. Финальный результат = вердикты LLM + решения → `scoring.compute()`.

### JSON-схема чек-листа
```json
{
  "name": "Базовый чек-лист CQA",
  "instructions": "Общие пояснения для LLM",
  "sections": [{"id": "security", "title": "Безопасность и решение"}],
  "criteria": [{
    "id": "04", "section_id": "security", "title": "Корректная и полная консультация",
    "description": "Что проверяем", "type": "binary | scale | flag", "weight": 20,
    "na_allowed": true, "na_condition": "Чат закончился до того, как клиент сформулировал запрос.",
    "scale": [{"value": 20, "description": "..."}, {"value": 0, "description": "..."}],
    "guidance": "доп. подсказка (опц.)"
  }]
}
```
Начальная конфигурация лежит в `backend/seed/default_checklist.json` и загружается при первом запуске.

### Адаптация под Dynamics 365
Фронтенд состоит из изолированных компонентов `mount(el, ctx)` без фреймворков и сборки, все стили лежат под корнем `.cqa`. Базовый URL API задаётся в `web/config.js` (`window.CQA_CONFIG.apiBase`), а CORS для своего домена — в `CORS_ORIGINS`. Папку `web/` можно загрузить как набор веб-ресурсов.

## Модель и стоимость

Все критерии оцениваются **одним вызовом** LLM на диалог. Цены Anthropic API за 1M токенов — вход / выход:

| Модель | Цена | Оценка одного диалога* | 65 диалогов DEV |
|---|---|---|---|
| `claude-opus-5-5` (по умолчанию) | $4 / $20 | ≈ $0.07–0.08 | ≈ $5 |
| `claude-sonnet-5-5` | $2 / $10 | ≈ $0.03–0.04 | ≈ $2.5 |
| своя модель на GPU | аренда GPU | — | — |

\* Оценка: ~4–6 тыс. входных токенов (инструкции и чек-лист ~2.5 тыс., транскрипт 1–3 тыс.) + ~1.5–3 тыс. выходных (вердикты и рассуждения при `effort=medium`). Повтор при невалидном ответе случается редко и стоит столько же. **Фактическая стоимость** каждой оценки считается по `usage` из ответа API (с учётом кэша промпта) и показывается в карточке и в пакетной оценке. Цены можно переопределить через `PRICE_INPUT_PER_M` / `PRICE_OUTPUT_PER_M`.

Для отказов модели (`refusal`) в адаптере Claude включён server-side fallback (бета `fallbacks: "default"`). Если бета недоступна, адаптер автоматически работает без неё.
