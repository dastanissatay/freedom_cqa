# CQA — Conversation Quality Analytics

[![tests](https://github.com/dastanissatay/freedom_cqa/actions/workflows/tests.yml/badge.svg)](https://github.com/dastanissatay/freedom_cqa/actions/workflows/tests.yml)

Система автоматической оценки работы операторов поддержки по диалогам (чаты и звонки, RU / KZ / EN) с помощью LLM.
Проект для хакатона Freedom Broker «CQA».

**Авторы:** Dastan Issatay, Askat Amandykov · команда **Qazyna**

## Что умеет

- **Настраиваемый чек-лист:** секции, веса, ответы Да/Нет и шкалы, N/A с условием, флаг грубой ошибки. Каждое сохранение — новая версия; новый или заменённый критерий работает без правки кода.
- **Оценка диалога** одним вызовом LLM. Баллы считает код, а не модель. По каждому критерию есть объяснение и ссылки на реплики. Для пропущенного действия указан участок, где оно ожидалось, для N/A — выполненное условие.
- **Карточка диалога:** транскрипт с подсветкой реплик-доказательств, у звонков аудиоплеер с переходом к моменту записи.
- **Апелляции:** оператор обжалует критерий, проверяющий подтверждает или меняет оценку, итог пересчитывается без повторного вызова LLM.
- **Пакетная оценка** набора по `group_id` с прогрессом и выгрузкой `results.json` в формате организаторов.
- **Аналитика по набору:** какие критерии нарушаются чаще всего, разрезы по языку и каналу, грубые нарушения.
- **Контроль качества самой LLM:**
  - эталонная ручная разметка и отчёт о согласии (процент совпадения, каппа Коэна, расхождения);
  - проверка стабильности повторным прогоном.
- **Маскирование персональных данных** (ИИН, карты, IBAN, телефоны, e-mail) перед отправкой транскрипта в LLM.

## Запуск

Требуется Python 3.11+.

```bash
git clone https://github.com/dastanissatay/freedom_cqa.git
cd freedom_cqa
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # заполнить, см. таблицу ниже
uvicorn app.main:app --app-dir backend --port 8000
```

Интерфейс: http://localhost:8000 · Swagger: http://localhost:8000/docs

| Переменная `.env` | Значение |
|---|---|
| `DATASET_API_URL` | URL API организаторов; `group_id` подставляется из интерфейса |
| `LLM_PROVIDER` | `anthropic`, `openai_compat` (vLLM / Ollama / OpenRouter) или `mock` |
| `ANTHROPIC_API_KEY` | ключ Claude API |
| `LLM_MODEL` | `claude-opus-5-5` (по умолчанию) |
| `TEAM_NAME` | название команды для `results.json` |
| `PII_MASKING` | `true` — маскировать персональные данные в промпте |

Ключи хранятся только в `.env`, он исключён из git.

**Без ключа:** укажите `LLM_PROVIDER=mock`, введите в шапке `group_id` = `SAMPLE` и импортируйте `data/sample_dataset.json` кнопкой «Импорт JSON».

**Своя модель:** `LLM_PROVIDER=openai_compat`, `OPENAI_BASE_URL=http://<host>:8001/v1`, `LLM_MODEL=<модель>`. Адаптер передаёт `temperature=0` и JSON-схему ответа.

## Как устроено

```
web/  (HTML + JS, ES-модули без сборки)  ──REST──▶  backend/app  (FastAPI + SQLite)

транскрипт ─▶ prompt.py ─▶ llm/ ─▶ validation.py ─▶ scoring.py ─▶ итог
              (из конфига   (адаптер)  (повтор при    (детерминированный
               чек-листа)              ошибке)        расчёт)
```

| Модуль | Назначение |
|---|---|
| `dataset.py` | прокси к API организаторов (обход CORS), кэш наборов, смещения реплик для аудио, аудио-прокси с Range |
| `checklists.py` | чек-листы с неизменяемыми версиями |
| `prompt.py`, `pii.py` | промпт и JSON-схема ответа строятся из чек-листа; маскирование ПДн |
| `llm/` | адаптеры `anthropic` / `openai_compat` / `mock`, модель меняется в `.env` |
| `validation.py` | проверка ответа LLM: все критерии, допустимые значения, N/A только где разрешён, существующие реплики |
| `scoring.py` | расчёт баллов (чистые функции, юнит-тесты) |
| `evaluator.py` | оценка диалога и проверка стабильности |
| `appeals.py` | апелляции и пересчёт финального итога |
| `batch.py`, `export.py` | пакетная оценка; выгрузка `results.json` и CSV |
| `analytics.py`, `references.py` | сводка по набору; эталонная разметка и согласие с LLM |

**Контракт LLM.** Модель возвращает только вердикты. Формат задаётся через structured outputs, JSON-схема генерируется из чек-листа:

```json
{"verdicts": [{"criterion_id": "03", "answer": "no", "explanation": "…", "evidence": [5, 7], "checked_range": [3, 8]}]}
```

Реплики в промпте пронумерованы `[i] speaker timestamp: text`. Оценивается только `operator`, а `bot` и `system` служат контекстом. Объяснения пишутся на русском. Невалидный ответ отправляется на повтор со списком ошибок.

**Расчёт** (`scoring.py`):
- «Да» — полный вес, «Нет» — 0, шкала — `ступень / максимум × вес`.
- N/A исключается, его вес перераспределяется: `итог = набранное / вес_применимых × 100`, округление до 2 знаков.
- Если применимых критериев нет, итог — `null`. Флаг грубой ошибки на баллы не влияет.

**Хранилище** (SQLite):
- `checklists`, `checklist_versions` — чек-листы и их версии;
- `conversations` — диалоги наборов;
- `evaluations` — оценки, со ссылкой на версию чек-листа;
- `appeals` — апелляции: исходное значение, решение, новое значение, причина, время;
- `reference_labels` — эталонная разметка.

**Dynamics 365.** Фронтенд собран из изолированных компонентов `mount(el, ctx)` со стилями под корнем `.cqa`. Базовый URL API задаётся в `web/config.js`, поэтому папку `web/` можно встроить как веб-ресурс.

## Результаты

| Файл | Набор | Записей |
|---|---|---|
| `results/dev/results.json` | DEV | 65 (60 чатов + 5 звонков) |
| `results/prod/results.json` | FBroker (контрольный) | 10 |

Обе выгрузки сделаны чек-листом из ТЗ (версия 1) моделью `claude-opus-5-5`. Выгрузить заново можно кнопкой «results.json» в «Пакетной оценке» или скриптом:

```bash
python scripts/export_results.py --group FBroker --out results/prod/results.json
```

Коды критериев (`contact`, `discovery`, …) берутся из поля «Код для выгрузки» в чек-листе. Реплики нумеруются с 1, как требует формат.

## Замеры

77 оценок моделью `claude-opus-5-5` (`effort=medium`), один вызов LLM на диалог:

| | DEV (67 оценок) | FBroker (10 оценок) |
|---|---|---|
| Стоимость одной оценки | в среднем $0.032 (медиана $0.030, максимум $0.064) | в среднем $0.034 |
| Всего | $2.17 | $0.34 |

- Повторный вызов из-за невалидного ответа понадобился в 4 оценках из 77.
- Время — около 12 с на диалог.
- Инструкции и чек-лист кэшируются (prompt caching), поэтому повторные оценки тем же чек-листом дешевле.
- Фактическая стоимость каждой оценки считается по `usage` из ответа API и показывается в интерфейсе.

40 тестов на mock-модели: расчёт (включая пример из ТЗ → 85.38), валидацию ответа LLM, генерацию промпта из конфига, сквозной сценарий «импорт → оценка → апелляция → пересчёт», выгрузку `results.json`, маскирование, сводку и стабильность. Тесты запускаются в GitHub Actions при каждом push.

## Ограничения и что дальше

- SQLite и очередь пакетной оценки в памяти процесса подходят для прототипа. Для продакшена нужны Postgres или Dataverse и очередь задач с отдельными исполнителями.
- Авторизации нет (по ТЗ): роли «Оператор» и «Проверяющий» переключаются в интерфейсе. Дальше — вход через Entra ID и роли Dynamics 365.
- Маскирование ПДн работает на регулярных выражениях, поэтому ФИО, адреса и кодовые слова не скрываются. Полная локализация данных возможна с локальной моделью через `openai_compat`.
- Качество оценки проверено только на собственной эталонной разметке: в данных организаторов эталона нет.
- Интеграция с Dynamics 365 сейчас — только веб-ресурс. Следующий шаг — записывать результаты обратно в Dataverse.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/datasets/{group_id}/conversations` | список диалогов (загрузка из API при пустом кэше или `?refresh=true`) |
| GET | `/api/conversations/{group_id}/{id}` | диалог |
| GET/POST | `/api/checklists`, `/api/checklists/{id}/versions` | чек-листы и версии |
| POST/GET | `/api/evaluations`, `/api/evaluations/{id}` | оценка: исходный и финальный результат |
| POST | `/api/evaluations/{id}/stability` | проверка стабильности |
| POST | `/api/appeals`, `/api/appeals/{id}/decision` | апелляция и решение |
| POST/GET | `/api/batch`, `/api/batch/{id}` | пакетная оценка |
| GET | `/api/export/{group_id}?fmt=results\|csv` | выгрузка |
| GET | `/api/summary`, `/api/quality` | аналитика; согласие с эталоном |
| GET | `/api/audio/{group_id}/{id}` | запись звонка |
